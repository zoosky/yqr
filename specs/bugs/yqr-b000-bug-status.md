The filing found a **second and larger** source this row had missed: the block-scalar content loop writes the block's indent before every line including empty ones, which across noyalib's own corpus is 36 documents to the indicator's 9. It surfaced by holding the fix to a *property* (no emitted line carries trailing whitespace) rather than to the reproduction, which the first fix already satisfied. Both faces are one cause — duplicated logic drifted from a sibling that applies the rule, the block-scalar loop existing in three identical copies — so the patch extracts a rule per site rather than patching callers | `yqr-f017`, `yqr-b015`, `yqr-a001` |

Upstream's, not yqr's — the flow class is delegated to `Document::remove` (`yqr-f016` §5) and calling it directly produces the same bytes. ## Summary

- Total bugs: 16
- Open: 2 — `b016` and `b015`, both trailing whitespace written by noyalib
  where a line should have ended, one on the emit path and one on the write
  path, and both found by producing a shape nobody had produced before.
  - **b016** — the emitter writes `value: ` before a block collection reached
    through a sequence item, *and* the block's indent before an empty
    block-scalar line. Pre-existing and reachable through `--normalize` since
    long before `yqr-f017`, which found the first face because `to_entries`
    output is exactly that shape; the second was found while fixing it, by
    measuring against the property rather than the reproduction. Not worked
    around in yqr: a blanket line-strip in `render` was measured to change a
    block scalar's value. Filed as noyalib#297 with a fix in noyalib#298.
  - **b015** — deleting a member of a *wrapped* flow collection leaves the
    removed member's indentation behind as a whitespace-only line. Upstream's
    `Document::remove`, which yqr delegates the flow class to. Valid YAML that
    loads back correctly, so Low; what it breaks is the diff, which is the one
    thing yqr promises to keep small. Unreachable until `b011` was fixed —
    the file could not be parsed. Filed 2026-08-20 as noyalib#294 with a fix
    in noyalib#296, on the same self-inconsistency argument that carried
    `b010` and `b014`: the block path already takes a removed entry's whole
    line, indentation included.
- **noyalib 0.0.25 (2026-08-20) closed four at once** — `b011`, `b012`, `b013`
  and `b014` §3.1, all filed upstream on 2026-08-19, all released the next
  morning in [noyalib#287](https://github.com/sebastienrousseau/noyalib/pull/287)
  ("four fixes from @zoosky"). Three were yqr's commits, cherry-picked with
  authorship intact; the fourth, `b013`, was the one filed deliberately
  *without* a patch — a heuristic with a public API attached, so what it counts
  was the maintainer's call — and the maintainer made it. Each was verified
  against the **published** crate on its own reproduction rather than from the
  release notes (`yqr-f019` §3), and the `yqr-f018` §5 delegation revisit that
  `b014` gated was run and decided (`yqr-f019` §4).

  b010 — noyalib's reorder exchanged value bytes only, so every
